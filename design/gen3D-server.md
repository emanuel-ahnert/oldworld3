## Asset generation (gen3d)

All graphics for this project are generated by us. Never download or use third-party
assets (models, textures, sprites, icons), even free or CC0 ones.

### Setup
- This laptop (ThinkPad T495, Vega 8) has no usable GPU for AI models, so never install
  or run Stable Diffusion, TRELLIS, ComfyUI etc. here.
- Generation runs on a separate GPU box (RTX 3060 12 GB) in a container. Its address, the
  login, server paths and the rules for working on it are in `design/local/gen3d-access.md`,
  which stays out of the repository (git-ignored):
  - **SDXL base 1.0** for text → image
  - **TRELLIS.2-4B** for image → textured 3D mesh (PBR), with BiRefNet background removal
  - a FastAPI server on port 8000 with a single-worker job queue
- Talk to it with the `gen3d` CLI (stdlib Python, on PATH), configured with the server's URL
  and a token (env `GEN3D_URL` / `GEN3D_TOKEN`). Never print or commit the token.
- If the server can't be reached, ask the user. Don't try to fix the server from here.

### CLI
```
gen3d model "<object description>" -o <out.glb> [--seed N] [--faces N] [--texture N]
            [--negative "..."] [--steps N] [--raw] [--resolution 512|1024|1024_cascade] [-q]
gen3d model --image <in.png|jpg> -o <out.glb> [--seed N] [--faces N] [--texture N] [--resolution …]
gen3d image "<prompt>" -o <out.png> [--object] [--seed N] [--negative "..."] [--steps N]
# both `image` and text `model` also take ControlNet options (see "Pose and shape control"):
#   [--control <png>] [--control-type depth|openpose|canny|normal] [--control-scale 0.7] [--control-end 0.8]
gen3d fetch <job-id> -o <out>        # result of an earlier job; waits if it's still running
gen3d jobs [--limit N]               # recent jobs: id, status, kind, prompt
gen3d health                         # GPU/VRAM, queue length, which models are loaded
```
- Progress goes to stderr. On success stdout is JSON:
  `{"job", "files": [...], "seed", "used_seed"?, "timings", "server_dir"}`. `seed` is the one
  that reproduces the job; `used_seed` (text-to-3d only) is the SDXL seed that passed the check.
  On failure it exits non-zero with the server's error message.
- `gen3d model` writes `<out>.glb`, `<out-stem>.preview.png` (2×2 grid of rendered views)
  and, for text prompts, `<out-stem>.image.png` (the generated source image).
- `gen3d image` writes the PNG only. Without `--object`, the prompt is used as-is (good for
  textures, sprites, concept art). With `--object`, it adds "single object, white
  background", which makes a good input for a later `gen3d model --image`.

### Timing and queueing
- 3D job: about 2 min at best with models warm, 3–5 min if the server was idle and has to
  load them. Each rejected seed adds another SDXL run of 30–40 s. Image-only job: about 30–60 s.
- Jobs run one at a time and the rest queue. For several assets, submit them one after
  another in the background and fetch the results. Don't wait for each one in the foreground.
- If a wait gets interrupted (timeout, laptop sleep), the job still finishes on the server.
  Use `gen3d jobs` to find its id and `gen3d fetch <id> -o …` to get it.

### Writing prompts for 3D
- Describe exactly **one** object: what it is, its material, its style.
  For example: `"stylized fantasy health potion bottle, cork stopper, red liquid"`.
- Avoid words that make SDXL draw several objects or a sheet: "set", "collection", "pack",
  "variations", "asset sheet", "sprite sheet". "low-poly" causes the same problem; the
  server strips it, so control the polygon count with `--faces` instead.
- The server adds the prefix "a single …" and the suffix "one single object, centered, full
  view, isolated on plain white background, soft even studio lighting, no shadow, high
  detail", plus a matching negative prompt. `--raw` disables this, and also the "low-poly"
  stripping and the single-object check.
- **Automatic check (text-to-3d only):** the server removes the background and rejects the
  image if the object covers less than 2% of it, touches the outer 4 px, or has a second blob
  bigger than 4% of the object. It tries up to 3 seeds (`seed`, `seed+1`, …). If all fail, the
  job errors with `no clean single-object image after 3 tries`. Rephrase the prompt (simpler,
  "one", a clear silhouette), or generate an image with `gen3d image --object` and pass it
  via `--image`. Neither `gen3d image --object` nor `--image` is checked, so look at that
  image yourself.
- No img2img. All outputs are static meshes, never rigged or animated.

### Pose and shape control (ControlNet)
- `--control <png>` conditions SDXL on a control image with the ControlNet-Union for SDXL
  (`xinsir/controlnet-union-sdxl-1.0`, Apache-2.0). The image follows its pose and silhouette
  and **takes its size** (rounded to multiples of 8, at most about 1 megapixel), so a result
  lines up pixel for pixel with the control image.
- `--control-type`: `depth` (default; near = white, background black), `openpose` (standard
  OpenPose stick figure on black), `canny` (white edges on black), `normal` (normal map).
- `--control-scale` (default 0.7): how strongly to follow it. Lower lets the subject deviate
  more (bulky armor over a slim body), higher sticks closer to the silhouette.
- `--control-end` (default 0.8): stop following it after this fraction of the steps. Lower
  frees the fine details and outlines.
- Use: render a depth map of a base body (`tools/pipeline/control.py`) and generate outfits
  with it, so every outfit stands in exactly the body's pose and proportions.
- The first controlled job after a start or idle unload loads an extra pipeline (slower).
  The control image is kept in the job directory as `control.png`.
- **Flat models:** style words like "hand-painted" or "illustration" make SDXL paint a flat
  2D picture, and TRELLIS turns it into a flat card (seen from the side, a tree was a thin
  slice). Ask for "3D render of …, three-quarter view, game asset, soft studio light" and put
  "flat, 2D, painting, illustration" into the negative prompt. Get the painted look from the
  textures and shaders instead.
- Best results come from a clear silhouette, a 3/4 view and a solid object. Thin wires,
  transparency, fur and text come out poorly.

### Always review the result
**Look at `<name>.preview.png` before using a model.** It shows 4 views. If rendering the preview
fails, the job still succeeds and the CLI skips the file without saying so. Then load the `.glb`
in Blender and render your own views. Reject and
regenerate (new `--seed` or a better prompt) if you see:
- several objects, floating shards or a fragmented surface
- a missing or cut-off part
- the wrong object, or a texture smeared over the geometry
Also look at `<name>.image.png`. If the source image is wrong, the 3D model will be too.

### Output format
- glTF binary (`.glb`), **Y-up**, fitted into a unit cube (the *largest* dimension is about 1,
  not necessarily the height), centered at the origin, one mesh.
  Scale and position it in the engine.
- A PBR material with a base-color texture and a metallic/roughness texture. There is no
  normal map; the geometry carries the detail. (Checked 2026-11-12 on a test job: one node,
  one primitive with POSITION/NORMAL/TEXCOORD_0, no skin or animation, `--faces 5000` gave
  4.7k triangles, `--texture 512` gave two 512² PNGs, written by trimesh.)
- `--image` with an RGBA PNG: the alpha channel is used as the mask and background removal
  is skipped (tested: an image with half the object made transparent produced only that half).
  Use this to choose exactly what gets built, e.g. mask a weapon out of a character picture.
  Image jobs write no `.image.png`.
- Defaults: 50k faces and 2048² textures (about 12 MB). Suggested budgets:
  - small prop or pickup: `--faces 5000 --texture 1024`
  - normal prop: `--faces 20000 --texture 2048`
  - hero asset: `--faces 100000`
- Resolution `512` is the default and the one tested on 12 GB. `1024` / `1024_cascade` give
  more detail but are slower and may run out of VRAM. Only try them for important assets.
- Keep the seed you passed (or `params.seed` from the job), not `used_seed`, in the asset
  manifest. After a rejected attempt SDXL uses `seed+i` but TRELLIS still uses the original
  seed, so only the original seed reproduces the 3D result. Every job is also archived on the
  GPU box; the manifest's `server_dir` is the job's folder in that archive (`<date>/<job>`).

### HTTP API (fallback if the CLI doesn't cover something)
Base `$GEN3D_URL`, header `Authorization: Bearer <token>`, multipart form
fields. Every POST returns a job object right away. Poll `GET /jobs/{id}` until `status`
is `done` or `error`.

| Method and path | Fields / notes |
|---|---|
| `POST /text-to-3d` | `prompt` (required), `negative`, `seed`, `steps` (30), `cfg` (6.5), `resolution` (`512`), `faces` (50000), `texture` (2048), `raw_prompt` (false); the same optional ControlNet fields |
| `POST /image-to-3d` | `image` (file, required), `seed`, `resolution`, `faces`, `texture`, `name`. An RGBA image with transparency skips background removal |
| `POST /text-to-image` | `prompt` (required), `negative`, `seed`, `steps`, `cfg`, `raw_prompt` (true); optional ControlNet: `control_image` (file), `control_type` (`depth`), `control_scale` (0.7), `control_end` (0.8) |
| `GET /jobs/{id}` | `status` (queued/running/done/error), `stage`, `queue_position`, `error`, `files`, `params` (incl. `seed`, `used_seed`), `attempts`, `timings`, `peak_vram_mb` |
| `GET /jobs/{id}/files/{name}` | download `model.glb`, `preview.png`, `image.png`, `input.png`; `rejected_N.png` only for failed jobs |
| `GET /jobs?limit=N` | recent jobs, newest first |
| `GET /health` | no auth. `ok`, `cuda`, `vram_free_mb`, `vram_total_mb`, `queued`, `loaded` (sdxl, sdxl_controlnet, trellis) |
| `GET /client/gen3d`, `GET /client/CLAUDE.md` | no auth. The latest CLI and this file |

Example:
```
curl -H "Authorization: Bearer $GEN3D_TOKEN" -F prompt="iron lantern" -F faces=10000 \
     "$GEN3D_URL/text-to-3d"
```

### Asking the GPU box
Logs, job archives and a Claude instance on the GPU box itself are reachable over SSH; how,
and what may be changed there, is in `design/local/gen3d-access.md`.

### Troubleshooting
- `cannot reach …`: the GPU box is off, asleep, or the server is stopped. Ask the user.
- `HTTP 401`: wrong token in the gen3d config.
- Job error containing `out of memory`: something else is using the GPU (usually a game).
  Retry later, or use resolution `512`.
- `interrupted by server restart`: resubmit the job.
- To update the CLI: download `$GEN3D_URL/client/gen3d` over the old one.
